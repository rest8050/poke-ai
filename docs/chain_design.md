# 사슬 아키텍처 설계 (2026-11-01, 구현 전)

## 가설과 목적
- 몸통은 이미 여러 턴 뒤 정보를 담고 있다 (future_probe: 동결 잠재가 3~6턴 뒤 생존/HP 우위를 원시 특징보다 MSE 0.675배로 예측, 승패 AUC 0.855 > FP 가치 0.708).
- 그런데 정책은 교체/테라/교사 확신 높은 결정에서 정체한다 (파라미터, loop, 히스토리, 데이터 증가 모두 null).
- 가설: 병목은 "정보 부족"이 아니라 정보를 **응수 비교로 바꾸는 경로**다 (상대가 무엇을 할지 -> 내 수마다 그 뒤 결과 -> 가치 비교).
  현재 헤드는 잠재 하나에서 정책을 바로 읽어서 이 경로가 암묵적이다. 사슬은 이 경로를 구조와 중간 정답으로 **명시**한다.
- 이 가설이 틀리면(아래 게이트) 방향을 접는다. 검색(3번)은 사슬의 동역학이 정확해야 쓸 수 있으므로 사슬이 선행한다.

## 구조 (몸통 `EntityPokemonNetV8`은 그대로, 헤드만 추가: `model_v9.py`, cfg `chain=true`)
입력은 기존 `latent`(256), 행동별 특징 `act_feat[a]`(기술 a: `active_mv`+`active_mon`, 교체 k: `my_mon[k]`+`cand[k]`; `_heads`의 `mv_in`/`sw_in`을 재사용), 상대 응수 임베딩 `o_emb[k]`.

1. **상대 응수 헤드 `p(o|s)`** (K개 클래스). 상대는 내 행동을 모르는 동시 선택이라 a에 의존하지 않는다.
   - 클래스(약 12): 공격(일반) / 공격(우선도) / 피벗 공격 / 능력 변화(셋업) / 회복 / 방어 / 설치(해저드·제거·필드) / 상태이상 / 기타 변화 / **교체**, 그리고 각 클래스에 **테라 동반** 플래그 1비트(별도 헤드).
   - 분류 기준: `data/move_classes.json`(11종) + Showdown 기술 우선도(우선도 있는 공격은 따로, `tools/gen_matchup_tables.js`에 우선도 열 추가). 교체 대상(어느 포켓몬)은 1차에서는 예측하지 않는다.
   - 정답: `data/dyn`의 `opp_action`(0 기술/1 교체/2 테라+기술/-1 불가/-2 강제교체 행), `opp_move`. -1,-2 행은 이 손실에서 제외.
2. **결과 헤드 `r(s,a,o)`** = MLP([latent, act_feat[a], o_emb[o]]) -> 한 턴 뒤 요약 `Δ`.
   - `Δ` = 양쪽 12마리의 HP 비율 변화 + 기절 여부 + 다음 결정 시점의 활성 슬롯(내 6, 상대 6, 분류) + 활성 부스트 5개 변화 + 상태이상 id(활성). `my_team_num`의 열 0 활성/1 기절/2 HP/3~7 부스트, `my_team_cat`의 열 4 상태를 다음 행에서 읽는다 (상대도 같은 열).
   - 정답: 같은 시퀀스의 다음 `kind=0` 행의 상태. 중간에 `kind=1`(강제 교체) 행이 끼면 그 행 전후를 보고 "이 턴에 기절 후 누가 나왔나"까지 이어 붙임. 새 변환 불필요(`data/dyn`에 이미 있음).
   - **라벨은 실제로 둔 수 a_taken, 실제 응수 o_actual 쌍에만 있다.**
3. **가치 헤드 `q̂(s,a,o)`** = MLP([r의 은닉, latent]) -> 승산 추정(0~1, 기존 value와 같은 척도).
   - **정책 경로**: `Q(s,a) = Σ_o p(o|s) · q̂(s,a,o)` (22행동 x K, 약 270회 MLP, 비용 무시 가능).
   - 정답: FP 탐색 점수 `q_mean[a]`(방문 수 `q_vis >= Q_MIN_VIS`인 행동만, 합법 행동 모두에 있음 -> 반사실 행동의 가치 신호). 기존 `q_terms` 재사용.
4. **정책**
   - 변형 A(보조): 기존 정책 헤드를 유지하고 사슬은 보조 손실만 (몸통이 사슬 신호로 더 좋은 표현을 갖는지 본다).
   - 변형 B(강제): `policy_logits = log_softmax(Q/τ)`를 정책으로 쓰고 증류 손실(교사 분포)을 여기에 건다 -> 정책이 사슬 경로를 **통과해야만** 나온다. τ는 학습 가능한 스칼라.
   - 추론: 변형 B는 사슬만, 변형 A는 기존 헤드. 둘 다 `0.5*policy + 0.5*Q-policy` 융합 평가도 측정(가중은 개발 세트에서만 고르고 시험 세트에서 확인).

## 손실
`L = L_policy(교사 분포 CE; 변형별 헤드) + 기존 value/hidden/pg 항 + λ_o·CE(p(o)) + λ_r·Huber(r; a_taken,o_actual 쌍) + λ_q·ΣMSE(Q, q_mean; 신뢰 행동만, q_vis 가중)`
- 초기값 λ_o=0.3, λ_r=1.0(정규화한 Δ 기준), λ_q=1.0. 개발 세트(학습 시드와 분리)에서 한 번만 조정.
- 몸통으로의 기울기: 사슬 손실은 몸통까지 흘린다 (그래야 변형 A가 의미). `r`의 입력 `o_emb`는 정답 응수를 teacher-forcing으로 학습(실제 응수), 추론에서는 `p(o)`로 가중.

## 학습 데이터와 방식
- 데이터: `data/dyn/*.npz`(48개, 3.10M행). 첫 파일럿은 **10% 하위 집합**(배틀 단위로 분할, holdout 규칙은 기존과 동일: 평가 풀은 학습에 쓰지 않음), 처음부터 학습, 6에폭, v8m과 같은 레시피(`--accum 4`, 피크 LR 1e-3 코사인).
- 새 코드: `src/core/model_v9.py`(헤드), `src/training/train_chain.py`(`train_fp_distill.run`을 감싸 사슬 손실 추가; 기존 스크립트는 건드리지 않음), `tools/chain_eval.py`(게이트 지표).

## 사전 등록 게이트 (파일럿 3개: P0 기준선 = 같은 10%의 v8m 구조, P1 = 변형 A, P2 = 변형 B)
치명 조건 (하나라도 실패하면 사슬 전제가 틀린 것으로 보고 키우지 않음):
- **M1 응수 예측**: `p(o)`의 시험 NLL이 클래스 사전 분포 대비 10% 이상 감소. (상대 행동이 상태에서 거의 예측 안 되면 첫 단계가 정보 한계.)
- **M2 조건부 사용**: 시험 세트에서 같은 배치 안 a 또는 o를 섞으면 결과 손실이 5% 이상 상대적으로 악화. (결과 헤드가 a, o를 무시하는 분포 평균 예측이면 사슬은 장식.)
성능 조건:
- **M3 Q 정책 품질**: Q 헤드 argmax의 학생 상태 regret이 정책 헤드 argmax 대비 +0.001 이내.
- **M4 이득**: P1 또는 P2의 학생 상태 regret(d7_ho, d6_ho, dg5, 짝지은 판 단위 부트스트랩)이 P0보다 CI가 0 아래일 때만 "개선". P2는 P0 대비 +0.002 이내면 "구조만으로 같은 수준", 이내를 넘어 나쁘면 변형 B 폐기.
- 개선이 확인되면 전체 데이터로 키우고 아레나(SPRT)와 FP300 승률로 확인.

## 반사실 검증 (게이트 M5, 선택, 시뮬레이터)
- 문제: 학습 라벨은 둔 수에만 결과가 있다. 안 둔 수의 결과 예측이 맞는지는 이 데이터로 못 잰다.
- 해결: `tools/scenario_gen.js`를 확장해 같은 위치에서 (내 모든 수 x 상대 응수 클래스 대표 수) 한 턴을 시뮬레이터로 전부 돌려 정답 Δ를 얻는다 (위치는 임의 팀 + 임의 합법 수의 짧은 전개로 생성, 수백 개).
- 지표: 반사실 Δ 예측 오차, 수 순위(내 HP 이득 기준) 상관. 이게 통과하면 사슬 동역학을 3번(깊이 2 검색)에 쓸 수 있고, 시뮬레이터 라벨을 학습에도 섞을 수 있다 (엔진은 이 PC 연구용; 서버 배포와 무관).

## 알려진 한계
- `Δ`는 요약 수준이라 검색에서 다음 상태를 인코더에 다시 넣으려면 토큰 단위 상태 갱신기가 따로 필요하다 (3번 단계의 별도 설계; 지금은 요약으로 사슬 가설만 검정).
- 상대 응수는 FP 자가대전 분포라서 사람/다른 모델 상대에게는 분포가 다를 수 있다.
- 교체 대상 예측 없음 (교체 응수는 한 클래스).
- 상태 갱신(교체 직후 입장 효과 등)은 `Δ`에서 활성 슬롯 변화로만 반영된다.
- 파일럿이 10%라서 용량이 큰 효과는 못 본다. 게이트는 "신호가 있나"를 보는 용도이고 최종 판정은 전체 데이터에서 한다.

## 구현 순서
1. `tools/gen_matchup_tables.js`에 기술 우선도 추가 -> 응수 클래스 테이블 `data/opp_classes.json`.
2. `data/dyn` 로더에 다음 상태 정답(`Δ`)과 클래스 정답 생성 (`src/training/chain_targets.py`, 단위 테스트: 합성 시퀀스로 Δ가 기대값인지).
3. `model_v9.py` 헤드 + `tests/test_model_v9.py`(출력 형태, 변형 A/B, 마스크).
4. `train_chain.py` + 파일럿 P0/P1/P2 (한 번에 하나씩, 동시 학습 금지).
5. `tools/chain_eval.py`로 M1~M4, 필요하면 M5.
